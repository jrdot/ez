# Backend 공통 — 업무 범위·워크플로우·인계 기준

## 기준과 읽는 순서

1. [사용자 요구사항 규격서](../../core/USER_REQUIREMENTS_SPEC.md)와 [설계 규격서](../../core/DESIGN_SPEC.md)를 읽는다.
2. [전역 공통 업무](../common.md)를 읽고 담당 작업의 범위와 계층 간 책임을 확인한다.
3. 해당 작업 문서와 실제 코드·테스트를 확인한다. 현재 DB 작업은 [BE-01 — PostgreSQL 영속화와 무결성](01-DATABASE.md)이다.

core에 구체화되지 않은 인증·클라우드·API 계약은 확정 요구로 간주하지 않는다. 기존 DB 구현 결정은 해당 작업의 기록이며 현재 프런트엔드 문서 포맷과의 호환성을 자동으로 보장하지 않는다. 연동 작업에서 버전·검증·변환 계약을 확인한다.

## 업무 범위와 경계

- 백엔드는 서버 서비스, HTTP 계약, 서버 권한 검증, 저장소와 DB의 스키마·제약·트랜잭션·마이그레이션을 담당한다.
- 프런트엔드는 화면·입력·로컬 편집 흐름을 담당한다. 서버 연동 시 입출력·오류·취소·충돌 계약을 함께 정하고 각 영역 문서에 반영한다.
- 파일 포맷과 도메인 의미 검증, DB의 저장 무결성 검증을 구분한다. 실제 검증 범위는 작업 문서에 기록한다.
- 설치·환경설정·운영 명령은 [백엔드 실행 안내](../../../backend/README.md)에서 관리한다.

## 작업 순서와 완료 기준

현재 문서화된 작업은 BE-01 DB 기반이다. 저장 단위·권한·버전 계약 확인 → 스키마·마이그레이션 → 저장소 구현 → 무결성·권한·동시성 검증 순서로 진행한다. 세부 결정과 구현 기록은 [DB 작업 문서](01-DATABASE.md)를 따른다.

인증·프로젝트 HTTP API는 아직 연결하지 않았다. 후속 작업은 core와 선행 계약을 확인한 뒤 별도 번호의 작업 문서로 정의한다. DB 기반 완료를 서비스 전체 완료로 표시하지 않는다.

작업 결과에는 대상 규격 또는 후속 설계 항목, 변경된 계약·파일, 검증 명령과 결과, 미구현 범위, 다음 작업의 시작 조건을 기록한다. 문서 작성·샘플 연동·실제 서비스 연동 상태를 구분하고, 별도 인계 문서가 생기면 같은 작업 번호로 연결한다.
