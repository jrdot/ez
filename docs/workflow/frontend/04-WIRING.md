# FE-04 — 배선, 분기, 교차, Preview

선행: FE-03의 실제 Terminal·부품 변환과 FE-01의 명령/연결 그래프. 목표는 화면에 보인 예상 연결과 실제 저장된 연결이 일치하는 것이다.

## 불변 조건

- 확정 Wire의 양 endpoint는 존재하며 연결 가능한 Terminal 또는 Junction이다. 빈 공간에는 확정하지 않는다.
- 하나의 Terminal에 복수 Wire를 허용한다. Wire 모드의 Terminal Drag는 위치를 바꾸지 않는다.
- 90° Wire는 수평/수직 선분만, 45° Wire는 수평/수직/45° 대각 선분만 가진다. Free Wire는 endpoint 두 개를 잇는 직선이며 Bend가 없다.
- Bend 이동/삭제는 연결 의미를 바꾸지 않는다. Junction은 실제 전기 연결을 갖는다.
- 교차만으로 연결되지 않는다. 분기가 아닌 모든 배선 교차에 반원 Jump를 표시한다.
- Preview는 확정 문서와 구별되며 문서·이력·저장 대상에 포함하지 않는다.

## 생성 상태 머신 — 구현 제안

| 상태 | 입력 | 결과 |
|---|---|---|
| 대기 | 연결 대상 접근 | Terminal/Junction/기존 Wire 중간 후보 표시 |
| 시작 후보 | 유효 대상 클릭 | 시작 대상 선택, 경로 Preview 진입 |
| 경로 Preview | 포인터 이동 | Snap, 경로, 절곡, 분기/교차 예상 결과 갱신 |
| 경로 Preview | 유효 종료 대상 클릭 | 전체 검증 후 Wire와 필요한 Junction을 한 명령으로 확정 |
| 경로 Preview | 유효하지 않은 공간 클릭 | 확정하지 않고 현재 상태 유지, 불가 상태 표시 |
| 임의 진행 상태 | Esc/모드·페이지 전환/취소 | 임시 경로·분기 정리 |

세부 클릭 순서는 DES §20 미정 항목이다. 위 2 endpoint 클릭 방식을 시작안으로 기록한다. 수동 경유점 클릭, 연속 배선, 더블클릭 종료를 필수 동작처럼 추가하지 않는다.

분기 후보 클릭은 실제 Junction 생성 확정 의사로 처리한다. 시작점을 Wire 중간으로 선택한 경우 해당 Junction은 진행 중 트랜잭션에 포함하고, 새 Wire가 완료될 때 함께 커밋하는 방식을 제안한다. 후보 클릭 직후 영구 저장하는 방식을 선택한다면 취소 시 고아 분기가 남지 않도록 롤백해야 한다. 이 시점 정책을 결정하고 Preview/Undo 테스트에 반영한다.

## FE-04A: 경로 생성과 Preview

1. endpoint 해석, 월드 위치 계산, 후보 검색, 경로 생성, 검증을 순수 함수로 분리한다.
2. 90°는 직교 경로 후보, 45°는 허용 각도 후보 중 결정적인 경로를 선택한다. 우선 축·짧은 경로·동률 처리·오차 허용값은 구현 결정으로 남긴다. 장애물 회피는 확정 요구가 아니며 부품 위 통과 정책을 별도로 결정한다.
3. Free는 두 endpoint만 계산한다. 색상·두께 설정을 생성 Preview와 확정 Wire에 동일 적용한다.
4. 단자·Junction 후보·Snap 위치·경로·90°/45° 꺾임·교차·연결 상태를 모두 Preview한다. 색상만으로 상태를 구분하지 않고 점선/투명도/형태 등을 사용한다.
5. 클릭 확정 시 같은 후보 해석·경로 생성 함수를 다시 검증한다. 이전 포인터 이벤트의 오래된 후보를 커밋하지 않는다.

시작/종료가 같은 대상인 경우, 중복 Wire, 길이 0, 연결 불가·숨긴 단자의 처리 정책을 정한다. Snap Off의 일반 위치 보정과 REQ-WIRE-JUNCTION-003의 분기 후보 Snap을 구분하고, 배선 연결 후보 판정은 유지하는 방식을 제안한다. Grid Snap 때문에 endpoint가 단자에서 떨어져서는 안 된다.

## FE-04B: Junction과 Crossover

- 기존 Wire의 선분에 포인터를 투영해 분기 후보를 계산한다. Bend와 기존 Junction 근처의 중복 후보를 정리한다. 여러 Wire가 겹친 곳의 대상 선택 정책을 명시한다.
- 새 Wire의 **시작과 끝 각각** 기존 Wire 중간을 선택할 수 있어야 한다. 클릭 전 Shadow Junction, 확정 후 명확한 실제 Junction을 표시한다.
- 원래 Wire와 새 Wire가 동일 Junction 노드를 참조하도록 만든다. 후보·경로·기존 Wire 갱신·새 Wire 생성은 하나의 명령이어야 한다.
- 교차 검출은 경로 geometry에서 계산하고 연결 판정은 그래프에서 계산한다. Junction과 Jump를 같은 연결 위치에 중복 표시하지 않는다.
- Jump를 어느 Wire에 그릴지, 반원 크기·방향, 확대/축소 시 크기 기준을 결정한다. 렌더링 장식이 원래 경로·hit test·전기 연결을 훼손하지 않게 한다.
- 모든 Wire 타입 조합의 일반 교차를 검증한다. 공선 중첩·끝점 접촉·다중 교차가 일반 교차와 어떻게 다른지 명시하고, 처리하지 못한 경우를 일반 교차 구현 완료에 숨기지 않는다.

## FE-04C: 경로 편집과 관련 객체 변경

1. 90°/45° 선분 Drag로 필요한 Bend를 생성하고 인접 선분을 보정한다. endpoint는 대상에 고정한다.
2. Bend 직접 이동은 90°에서 상하좌우, 45°에서 8방향이다. 45° 대각 이동만 원문에서 후속 연기가 허용된다. 연기할 때 4방향 구현, 누락 방향·사유·후속 검증을 기록한다.
3. Bend 삭제 시 중복점·길이 0·불필요한 동일 방향 선분을 제거하고 타입별 각도 조건을 재검증한다. 유효 경로를 만들 수 없는 경우 임의 연결 훼손 대신 편집을 거부하거나 보정하는 정책을 정한다.
4. Free Wire에서는 Bend 생성/편집을 제공하지 않는다. 일반 선분 Drag 요구와 Free의 두 endpoint 직선 규칙을 함께 지키도록, 경로 Drag를 비활성화하는 것을 제안한다.
5. 부품 이동/회전·단자 수정 시 endpoint 위치를 다시 계산한다. Junction이 있는 경로의 편집은 분기 위치/연결 보존 규칙까지 포함한다.
6. 부품·Terminal·Wire·Junction 삭제 시 관련 Wire를 함께 삭제할지, 삭제를 제한할지 결정한다. endpoint가 없는 Wire를 남기지 않으며 Undo에서 ID·연결을 함께 복원한다. Wire 타입 변경 때 Free로 바꾸면 Bend 제거와 분기 보존을 어떻게 처리할지도 결정한다.

## 완료 기준

- Terminal→Terminal, Terminal→Junction, Junction→Terminal, Junction→Junction 생성과 한 Terminal의 복수 연결.
- 기존 Wire 중간에서 시작/끝내는 양방향 분기 생성, 후보 취소 시 문서 불변, 한 번의 Undo로 분기 관련 변경 전체 복원.
- 3타입 경로·색상·두께, 선분 Drag/Bend 이동·삭제, Free의 Bend 없음.
- 비연결 교차는 Jump, 실제 연결은 Junction. Preview와 확정 결과의 연결·경로 일치.
- 이동/회전·삭제·페이지 전환·Esc·Undo/Redo 후 참조 무결성.
- 도메인: 각도·끝점·단순화·교차·분기 트랜잭션 테스트. E2E: 위 생성·취소·편집 흐름. 시각 검증: 여러 줌에서 Shadow/Junction/Jump 구별.

인계: 확정 경로/연결 계약, 혼합 타입·분기·교차 fixture, 미정 edge case와 허용된 연기 목록.

## FE-03에서 받은 계약

[FE-03 인계](03-OBJECTS-IMAGES-HANDOFF.md)의 `endpointPosition`, `connectionCandidate`, `connectedWires`, `transformCommand` 및 `public/objects-images-fixture.wireproj`를 사용한다. 변환은 단자 ID를 유지하고 최신 월드 위치를 계산한다. 실제 경로 재생성은 이 단계의 책임이다. 연결된 부품 삭제 거부와 숨긴 단자의 기존 연결 유효성은 유지한다. 내부 직접 Terminal→Terminal Wire 복사는 구현되어 있으며 Junction 포함 복사 범위는 FE-04에서 확장·검증한다. 배경 제거 외부 AI 대기는 배선 시작 조건이 아니다.
