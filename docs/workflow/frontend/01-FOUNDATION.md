# FE-01 — 계약과 편집기 기반

선행: [워크플로우](common.md), 두 규격서. 목적은 이후 화면과 배선이 같은 좌표·ID·상태·명령 계약을 사용하도록 만드는 것이다.

## 확정 요구

- 기본 문서: A4 가로, 흰 배경, 객체 Snap. A4/A3의 가로·세로 지원.
- 프로젝트 작업 페이지 최대 3개. 기본 이름 `EZ-001` 형식.
- Image/Line/Point/Text 객체마다 고유 ID. 그룹은 새 ID, 자식 ID는 유지.
- 부품은 복합 객체로 구성 가능하며 Terminal은 연결용 Point다.
- 배선 endpoint는 Terminal 또는 Junction 참조만 허용. Terminal에는 여러 배선 연결 가능.
- Bend는 경로 편집점, Junction은 전기적 연결점이다. Free 배선에는 Bend가 없다.

## 구현 순서와 제안 계약

1. 현재 타입·파일·샘플·테스트의 차이를 조사하고 모델 변경안을 기록한다. `Sheet`와 작업 페이지는 같은 개념으로 매핑한다.
2. 좌표 단위, 변환 원점, 회전 중심을 정한다. 제안은 문서 좌표와 CSS pixel을 분리하고 부품 내부는 로컬 좌표, 페이지는 월드 좌표로 두는 것이다. A4/A3 실제 크기와 내부 단위 변환은 한 모듈이 소유하고, 줌과 출력 DPI는 독립시킨다.
3. `activeSheetId`로 모든 편집 대상을 지정한다. 페이지 수 제한을 버튼과 도메인 명령 양쪽에서 검사한다. 생성 번호와 삭제 후 재사용 정책은 결정 기록에 남긴다.
4. 객체·부품 정의·인스턴스·연결의 참조 계약을 만든다. 페이지 간 endpoint 연결은 현 규격에 없으므로 추가하지 않는다.
5. 명령 실행·취소와 입력 Preview를 분리하고 파일 경계 검증을 보완한다.

다음은 개념 스케치이며 최종 저장 스키마가 아니다.

```ts
type SnapMode = 'object' | 'grid' | 'off';
type WireType = 'orthogonal' | 'diagonal45' | 'free';
type Endpoint =
  | { kind: 'terminal'; componentId: string; terminalObjectId: string }
  | { kind: 'junction'; junctionId: string };
// 객체: id, type, transform, 소유 페이지/부품/그룹 관계
// 배선: id, type, start, end, bends, junctionRefs, color, thickness
// 분기: id, 위치, 연결 배선 관계 — 여러 배선이 동일 분기를 참조
```

일반 Line은 전기 연결 Wire와, 일반 Point는 Terminal/Junction/Bend와 구분한다. 그룹은 자식 참조로 표현하고 순환·중복 소유를 금지한다. 부품 인스턴스 내부 객체도 ID 충돌이 없어야 한다. 라이브러리 정의의 ID를 모든 배치 인스턴스에 그대로 재사용하지 않는다. 복사 시 새 ID를 발급하고 내부 참조를 재매핑한다.

Terminal 최소 개념은 ID·위치·이름·표시 여부·연결 가능 여부·연결 Wire 목록이다. 연결 목록은 endpoint에서 파생하는 방식을 제안한다. 저장된 역참조를 사용한다면 양방향 갱신을 한 명령에서 보장한다. 숨김과 연결 불가는 별개이며 숨긴 단자의 선택/Preview 정책은 명시적으로 결정한다.

Junction은 공유 노드로 정규화하는 것을 제안한다. 기존 Wire 분할 또는 기존 Wire 내부 노드 참조 중 한 표현을 결정하고, ID 유지·삭제·이력·직렬화 규칙을 함께 정의한다. 화면상의 좌표 일치만으로 연결을 판정하지 않는다.

## 상태와 변경 경계

| 상태 | 예 | 이력/저장 제안 |
|---|---|---|
| 문서 | 페이지, 객체, 부품, 배선, 자산 참조 | 확정 명령 단위로 이력, 저장 계약에 포함 |
| 편집 | 활성 페이지, 선택 ID, 모드, 포인터, Preview | 문서 데이터에 섞지 않음 |
| 보기/UI | 줌·팬, 접힘, 대화상자 | 저장·이력 포함 범위 별도 결정 |
| 연동 | 로딩, 실패, 저장 상태 | 문서와 분리 |

`pointerdown → 임시 상태 → pointermove Preview → pointerup 검증 → 명령 1회`를 제안한다. `Esc`, pointer cancel, 포커스 상실·페이지/모드 전환 시 임시 상태 정리 규칙을 정한다. 취소한 작업은 문서·revision·이력을 바꾸지 않는다. Undo 범위는 미정이지만 추가/이동/회전/속성/삭제/그룹/배선·분기 변경을 한 사용자 동작 단위로 되돌리는 것을 기본안으로 한다. 새 명령 후 redo 분기는 폐기한다.

## 현재 파일 계약 검증

현재 규격에 맞는 문서와 샘플을 기준으로 읽기/쓰기를 검증한다. 폐기된 임시 모델의 호환·변환은 요구하지 않는다. 알 수 없는 버전, 깨진 중첩 배열, 중복 ID, 없는 endpoint, 유효하지 않은 크기/수치, 3개 초과 페이지를 검사한다. 불러온 데이터의 페이지·연결·이미지를 조용히 버리지 않는다.

## 산출물과 완료 기준

- 좌표·객체·배선·명령·호환성 계약, 샘플 문서, 타입/검증 함수.
- 새 프로젝트 기본값, ID 유일성/그룹 ID 보존, 최대 3페이지, 참조 무결성 테스트.
- 명령 하나의 실행→Undo→Redo가 동일 문서 내용과 연결 관계를 재현. revision 정책은 내용 복원과 별도로 검증.
- 기존 생성·열기·닫기 흐름 유지. 미정 계약은 영향받는 단계와 함께 인계.
