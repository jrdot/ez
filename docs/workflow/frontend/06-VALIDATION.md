# FE-06 — 통합 검증과 인계

선행: 각 단계 검증 결과, 계약 결정, [추적표](07-TRACEABILITY.md). 이 문서는 구현 시 실행할 계획이며 현재 테스트 통과를 주장하지 않는다.

## 검증 층

| 층 | 검증할 핵심 |
|---|---|
| 도메인/Vitest | 좌표·회전·스냅, ID 재매핑, 3페이지 제한, 배선 각도/endpoint, 분기·교차, 경로 단순화, 이력·파일 무결성 |
| UI 컴포넌트 | 모드·탭·접힘, 입력 포커스와 단축키 충돌, 속성 오류·혼합 값, 비동기 취소 |
| Playwright | 실제 입력으로 생성·배치·편집·배선·취소·복원·다운로드 |
| 시각 확인 | 5영역 고정 배치, 한 줄 요약, 줌 후 Grid, Shadow/Junction/Jump, 이미지 투명도, 출력 잘림 |

단순 스타일 변경에 구현을 그대로 복제하는 테스트를 추가하지 않는다. 데이터 불변 조건과 사용자 흐름을 우선하며 테스트 이름/검증 기록에 REQ ID를 연결한다.

## 핵심 인수 시나리오

1. **새 프로젝트/작업영역:** A4 가로·흰 배경·Object Snap·EZ-001 확인 → 모드 3개 전환 → 양쪽 Sidebar 접힘 → 3페이지 생성·4번째 거부 → 페이지별 객체 격리.
2. **탐색/배치:** Wheel·Shift Wheel·Ctrl/Alt Wheel·두 Pan 방식 → Grid 고정 확인 → 줌/팬 후 Library DnD → Object/Grid/Off 결과 확인 → 객체 겹침 허용.
3. **편집:** Click·Ctrl/Shift 토글 → 그룹 생성 시 자식 ID 유지 → 자유/45° 회전 → 복사/잘라내기/붙여넣기 ID 재매핑 → 속성·Delete → Undo/Redo → 폼 입력에서는 단축키가 문자 편집에 적용.
4. **이미지/단자:** 이미지 Paste→부품 추가 → Crop/배경 제거/Resize→등록/배치 → 부품 편집에서 단자 이동 → Wire 모드에서 단자 이동 금지 → 부품 회전 후 연결 위치 일치.
5. **배선:** 90°/45°/Free 각각 Preview 후 확정 → 같은 단자에 복수 연결 → 빈 공간 종료 거부 → 색/두께 변경 → 선분 Drag·Bend 이동/삭제 → Free에 Bend 없음.
6. **분기/교차:** 기존 Wire 중간 시작 및 종료를 각각 수행 → Shadow 클릭 확정 → 연결 Junction 표시 → 단순 교차에는 Jump → 줌/이동 후 표시 갱신 → Esc 시 취소 → Undo/Redo 시 관련 연결 일괄 복원.
7. **보조/연동:** 한 줄 선택 요약·System 배경·Full Screen → 상세 계약이 확정된 BOM/Table 검증 → 파일 왕복·PNG/PDF/Code 결과 검증. 미정 항목은 미실행 이유와 영향 ID 기록.
8. **회귀/오류:** 기존 생성/열기/닫기, ID 생성 fallback·실패, 잘못된 JSON·버전·깨진 endpoint·이미지 로드 실패. 편집 취소·저장 실패가 기존 문서를 손상시키지 않는지 확인.

45° Bend 대각 이동을 연기했다면 8방향 전체 통과로 기록하지 않는다. 외부 서비스 mock으로 성공한 테스트를 실제 배경 제거·공용 라이브러리 연동 증거로 쓰지 않는다.

## 실행 명령

저장소 루트에서 현재 `package.json`과 CI 설정을 확인한 뒤 실행한다.

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

E2E는 현재 `playwright.config.ts` 기준 Chromium과 개발 서버를 사용한다. 브라우저가 없는 환경은 설치 필요 여부를 기록한다. 실패는 신규 회귀/기존 실패/환경 제약으로 구분하고 해결 또는 인계한다. 문서만 변경하는 작업에서는 링크·ID·내용 정합성을 검사하고 앱 테스트를 실행한 것처럼 보고하지 않는다.

[전역 공통 문서](../common.md)의 초기 표시 2초 목표와 부품 100개·배선 300개 조작 목표는 성능 참고 기준이다. 적용 시 브라우저·기기·viewport·fixture·측정 구간·결과를 기록한다. 새 규격에 명시되지 않은 FPS나 기기 보장치를 임의로 출시 요건으로 만들지 않는다.

## 최종 인계 체크리스트

- [ ] 추적표의 모든 ID에 구현·검증·미정·허용 연기 상태가 기록되어 있다.
- [ ] 파일·자산·객체·연결 무결성과 Undo/Redo가 확인됐다.
- [ ] 핵심 사용자 흐름의 테스트/시각 증거와 명령 결과가 있다.
- [ ] 타입·샘플·어댑터·결정 문서가 실제 구현과 일치한다.
- [ ] 실패·미실행·외부 의존성·미정 계약에 영향 ID와 다음 작업이 있다.
- [ ] 구현한 단계와 전체 규격 충족 여부를 구분해 보고했다.

인계 결과는 워크플로우의 공통 형식에 맞춰 작성한다. 필요한 상세 결정이 남았다면 검증된 부분을 인계하고 남은 범위를 정확히 표시한다.
