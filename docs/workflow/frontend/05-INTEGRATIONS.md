# FE-05 — 보조 기능, 저장, 출력 연계

선행: FE-03/04의 문서·자산·연결 계약. 하단 진입점은 확정됐지만 BOM/Table/Code/출력/저장 상세는 미정이다. 이 단계는 상세 결정을 먼저 얻고 그 범위만 구현한다.

## 바로 구현 가능한 기능

- Zoom: FE-02 변환과 같은 상태/명령을 사용한다.
- Grid: 표시 전환. 간격 설정과 저장 범위는 확정 전 제안으로 남긴다.
- Snap: Object/Grid/Off 표시·변경. 기본 Object를 유지한다.
- Full Screen: 브라우저 진입·해제와 외부 Esc 해제를 UI 상태에 반영한다. 실패 상태도 처리한다.
- System: 확정 설정은 Canvas 배경색. 흰색 기본값과 변경 적용을 검증한다. 색 선택 UI·설정의 프로젝트/사용자 범위·영속성은 결정한다.
- Help: 진입점을 제공한다. 본문 범위는 미정이므로 확정된 조작표를 초기 콘텐츠로 사용하는 것을 제안한다.

## 구현 전에 결정할 계약

[전역 공통 문서](../common.md)의 전체 페이지 BOM 집계·수동 항목·IndexedDB 복구는 참고 제안으로 가져올 수 있지만, 새 상세 규격이 확정됐다고 표현하지 않는다. Code Download를 `.wireproj` 저장이나 펌웨어 생성으로 임의 정의하지 않는다. SVG/CSV 다운로드·가격·서버 로그인은 이번 규격에 없는 확장이다.

## 어댑터와 오류 계약 — 구현 제안

렌더러 밖에 `library`, `imageProcessing`, `projectPersistence`, `export` 경계를 둔다. 요청·성공 결과·사용자 취소·검증 오류·일시 실패를 구분하고, 중복 실행/프로젝트 전환 중 늦은 응답을 처리한다. 로딩·빈 결과·실패·재시도 UI를 명시한다. 서버가 없는 기능은 mock 완료와 실제 연동 완료를 구분해 인계한다.

파일 내보내기/열기는 이미지·부품 정의·단자·그룹·분기 참조를 보존해야 한다. 현 serializer의 빈 parts/assets 배열을 그대로 사용해 이미지 프로젝트 저장 완료로 선언하지 않는다. 저장 실패 후 현재 편집 문서를 유지하고 성공 표시를 하지 않는다. 저장 상세가 결정되기 전 기존 파일 열기 기능은 유지한다.

PDF/PNG는 확정 문서를 입력으로 받는 출력 레이어를 제안한다. 편집 핸들·선택·Shadow를 제외하고 Terminal·Junction·Jump·이미지의 출력 의미를 유지한다. 외부 이미지 디코딩·출력 가능 여부를 검사한다. 출력 대상·배경·Grid 포함 여부는 결정한 계약을 따른다.

## 완료 기준

- 하단의 모든 진입점이 구현/미정/연동 대기 중 어느 상태인지 명확함.
- System 배경·Grid·Snap·Zoom·Full Screen의 실제 동작 검증.
- 상세가 확정된 BOM/Table은 같은 문서의 실제 데이터와 일치. 공용부품은 실제 목록 연동 여부를 명시.
- 결정된 파일 저장 범위에서 serialize→parse 왕복이 객체·이미지·연결을 보존.
- 출력 계약 확정 후 빈 페이지·혼합 배선·이미지·분기·여러 페이지로 PDF/PNG를 열어 범위·잘림·품질 확인.
- 미정 기능은 요구사항 추적표 상태와 후속 결정 담당/질문에 남김. 해당 기능의 대기는 전체 기능 완료를 의미하지 않음.
