# 프로젝트 정의서 — 부품 배치·배선 웹앱

2026-09-30 · @Leedo · v2.1

## 1. 개요

실제 부품 이미지와 단자 정보를 기반으로 부품을 배치하고, 단자 사이 배선을 시각적으로 연결·편집·관리하는 웹 기반 작업 도구를 만든다(URS §1).

- **비전:** 내 부품을 쉽게 등록하고, 배선을 다시 그리지 않고 고치며, 결과물과 데이터를 자유롭게 꺼내 쓰는 배선 도구
- **풀려는 문제:** 기존 도구는 배선을 조금 고칠 때도 다시 그려야 하고, 라이브러리에 없는 내 부품을 넣기 어렵고, 만든 데이터가 도구 안에 갇혀 필요한 결과물을 꺼내 쓸 수 없다
- **만드는 이유:** 내 작업 도구로 쓰고, 이후 내 서비스로 운영하며, AI 에이전트 개발 방식도 익힌다

## 2. 목표와 성공 기준

**목표(초안):**

- 1차 완료 후 3개월 동안 새로 만드는 전자공작·임베디드 배선 도면을 기존 도구 없이 이 웹앱으로만 만든다
- 배선 수정은 다시 그리지 않고 편집만으로 끝낸다
- 도면에서 BOM·배선표를 손으로 옮겨 적지 않는다

**1차 완료 판정:** 기준 과제인 ESP32 + 센서 몇 개 도면을 기존 도구 없이 이 웹앱만으로 처음부터 끝까지 만들 수 있으면 1차 완료다. 이 과제는 그대로 E2E 테스트 시나리오가 된다. 기준 과제의 부품 구성과 배선 규모는 시나리오 문서에서 확정한다(10절). 1차에서 실사용을 검증하는 분야는 3절을 따른다.

- [ ] 부품 사진 한 장으로 단자가 있는 부품을 등록할 수 있다
- [ ] 기준 과제 도면을 완성할 수 있고, 배선 경로는 다시 그리지 않고 고칠 수 있다
- [ ] 의도하지 않은 연결이나 분기가 생기지 않는다 — 기준 과제 E2E에서 연결 그래프(어느 단자가 어느 단자와 이어졌는지)가 기대값과 일치
- [ ] PNG/PDF, BOM, 배선표가 도면 내용과 일치한다 — E2E에서 BOM 부품 목록·배선표 연결 목록이 연결 그래프와 일치
- [ ] 프로젝트 파일을 다시 불러오면 도면이 그대로 복원된다
- [ ] 자체 호스팅 서버에서 본인 로그인으로 동작하고 작업이 서버에 저장된다
- [ ] 모바일에서 저장된 도면을 볼 수 있다

## 3. 사용자와 역할

1차 사용자는 개발자 본인 한 명이고, 이후 외부 공개 서비스로 확장한다.

| 단계 | 사용자 | 의미 |
| --- | --- | --- |
| 1차 | 본인(개인 도구) | 내 작업에 실제로 쓸 수 있으면 완료 |
| 이후 | 불특정 외부 사용자 | 계정·공용부품·운영 정책 필요 |

다루는 배선 분야는 네 가지다. 특정 분야에 맞춘 기능보다 부품·단자·배선이라는 공통 모델이 중심이다. 1차는 전자공작·임베디드로 실사용을 검증하고, 나머지 분야는 데이터 모델이 분야별 속성을 담을 수 있는지까지만 확인한다(초안).

| 분야 | 1차 | 분야별로 필요한 속성(예) |
| --- | --- | --- |
| 전자공작·임베디드 (ESP32·아두이노 + 센서·모듈) | 실사용 검증 | 핀 이름, 전압 |
| 케이블·하네스 제작 | 모델 확장성만 | 전선 길이, 규격(AWG), 커넥터 핀배열 |
| 제어반·산업 배선 | 모델 확장성만 | 단자대 번호, 전선 번호 |
| 교육·문서용 도식 | 모델 확장성만 | 주석, 표기 |

**역할(초안):**

| 역할 | 담당 | 결정 권한 |
| --- | --- | --- |
| 본인 | 기획·검토·배포 | 최종 승인 |
| Claude | 구현·테스트·문서 초안 | 아래 단독 결정 범위 |

- **Claude 단독 결정:** 컴포넌트·모듈 구조, 내부 구현 방식, 테스트 추가, 동작을 바꾸지 않는 리팩터링, 문서의 오탈자·서식 수정
- **본인 승인 필요:** 기술 스택·외부 라이브러리 추가, 프로젝트 파일·부품 저장 형식 변경, 요구사항·범위 변경, 서버 배포와 데이터 삭제, 기존 테스트의 삭제·건너뛰기·기대값 변경, 정의서·URS·FDS의 내용 변경

## 4. 핵심 시나리오

대표 작업은 "내 부품을 등록하고, 배선을 그리고, 결과물 4종을 뽑는다"이다(URS에서 재구성, 2026-09-30 확정).

1. **부품 등록:** 부품 사진을 붙여넣거나 업로드하고, 자르기·배경 제거로 다듬은 뒤 단자 위치와 이름을 찍어 라이브러리에 저장한다.
2. **부품 배치:** 라이브러리에서 부품을 A4/A3 도면으로 끌어다 놓고 이동·회전한다.
3. **배선:** 배선 모드에서 단자를 차례로 클릭해 연결한다. 클릭 전 쉐도우 프리뷰(클릭하면 생길 배선을 미리 흐리게 보여주는 표시)로 결과를 확인하고, 필요하면 기존 배선 중간에 분기점(한 배선에서 다른 배선이 갈라지는 점)을 만든다.
4. **정리:** 선분을 끌어 경로를 다듬고, 절곡점(배선 경로가 꺾이는 점)을 추가·이동한다. 서로 연결되지 않은 배선이 교차하는 곳은 Crossover(반원 모양 교차 표시)로 구분한다. 색상·두께로 배선을 구분한다.
5. **결과물:** PNG/PDF 도면, BOM, 배선표를 내려받고, 프로젝트 파일로 저장해 나중에 이어서 작업한다.

모든 편집 단계에서 되돌리기·다시 실행(Undo/Redo)을 쓸 수 있다.

분야별 시나리오(하네스 핀배열, 제어반 단자대 등)는 별도 시나리오 문서에서 다룬다. 정식 정의는 용어집에서 확정한다.

## 5. 범위

1차는 편집 기능과 결과물 4종을 모두 포함한다. 계정과 공용부품처럼 외부 사용자를 전제로 하는 기능은 공개 단계로 미룬다. 기간 제약이 없으므로 기능 범위를 줄이지 않고, 순서는 8절을 따른다.

| 구분 | 포함 항목 |
| --- | --- |
| 1차 | 부품 등록·배치, 배선 편집(URS §2~17, 공용부품 탭 REQ-PUBLIC-LIBRARY-001 제외), Undo/Redo, 프로젝트 파일, PNG/PDF 도면, BOM, 배선표, 본인 로그인 |
| 공개 단계 | 사용자 계정, 공용부품 라이브러리 운영 — 시작 조건은 10절에서 확정 |
| 제외 | 실시간 공동 편집, 자동 배선(오토라우팅), 타 포맷(KiCad·Fritzing 등) 가져오기 |

**공개에 대비해 1차부터 지킬 것:** 부품과 프로젝트 파일에 M1부터 형식 버전을 표기해 이전 파일을 계속 열 수 있게 하고, 내 부품은 공용부품으로 옮길 수 있는 표준 형식으로 저장한다.

**프로젝트 파일(URS·참고 서비스의 "Code Download"):** 펌웨어 코드가 아니라 사용자 프로젝트 전체다. 내려받은 파일을 다시 불러와 이어서 작업하는 저장 형식이면서, 다른 도구·스크립트가 읽는 연동 데이터로도 쓴다. 이 문서와 이후 문서는 "프로젝트 파일"로 부르고, 배선표도 참고 서비스의 "Table" 대신 "배선표"로 부른다.

**BOM·배선표의 열과 길이 단위:** 배선표에 전선 길이를 넣을지, 넣는다면 도면 축척으로 계산할지 배선별로 입력할지는 URS 개정에서 정한다. 1차 기본안은 도면 축척 없이, 길이가 필요하면 배선 속성으로 직접 입력하는 방식이다(초안).

## 6. 제약·가정·비기능

혼자 Claude와 함께 개발하고 운영 중인 자체 호스팅 서버에 올린다. 기간 제약은 두지 않고 기능과 완성도를 우선하며, 부족한 점은 업데이트로 개선한다.

| 제약 | 내용 |
| --- | --- |
| 인원 | 본인 1명(기획·검토) + Claude(구현 중심) |
| 기간 | 제약 없음 — 완성도 우선, 반복 업데이트 |
| 배포 | 운영 중인 자체 호스팅 서버 |
| 기술 전제 | React(Next.js 등 메타 프레임워크 없이), Tailwind CSS. 나머지 스택은 ADR로 확정(부록 B) |

| 비기능 | 내용 |
| --- | --- |
| 기기·브라우저 | 데스크톱에서 편집: 최신 Chrome·Edge. 모바일은 보기만: iOS Safari·Android Chrome 최신 버전(초안) |
| 규모·성능 | 한 장에 부품 약 30개, 배선 약 100개. 이 규모에서 드래그 중 60fps 유지, 쉐도우 프리뷰는 마우스 이동 후 50ms 이내 갱신. 측정은 본인 개발 PC의 최신 Chrome 성능 패널 기준(초안) |
| 접근·보안 | 인터넷 공개, 본인 계정만 로그인, HTTPS(초안) |
| 데이터 저장 | M1~M3: 브라우저 내 저장(IndexedDB). 프로젝트 파일 내려받기·불러오기는 M2a부터 제공해 브라우저 데이터의 사본으로 쓴다. M4부터 서버 저장, 브라우저 내 데이터는 서버로 옮기는 가져오기 기능 제공(초안) |
| 데이터·백업 | 부품·프로젝트 파일에 형식 버전 표기. 서버 데이터는 매일 1회 백업·7일 보관하고, 복원을 M4 완료 전에 한 번 이상 시험(초안) |

**가정(초안):**

- 브라우저 내 배경 제거가 부품 사진에 실사용 품질을 낸다 — 확인: M1에서 실제 부품 사진 10장으로 시험, 7장 이상이 수동 보정 없이 쓸 수 있으면 통과. 미달이면 자동 제거는 보조 기능으로만 유지(7절)
- SVG 렌더링으로 부품 30개·배선 100개 도면이 원활하다 — 확인: M2a 시작 전 성능 시제품이 위 성능 기준을 통과(7절)
- 자체 호스팅 서버를 공개 단계까지 계속 운영한다 — 확인: M4 시작 전과 공개 단계 시작 전 재검토(7절)
- 참고 서비스의 구조·동작 참고는 사용 권리 문제가 없다 — 확인: URS 개정 전(10절)
